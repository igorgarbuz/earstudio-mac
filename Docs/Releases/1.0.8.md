EarStudio Companion 1.0.8 addresses Bluetooth service-discovery timeouts and improves recovery when audio is connected but the ES100 control channel will not open.

### Changes

- Use full Bluetooth service discovery instead of the UUID-filtered request that accepted queries without completing on the tested macOS 15.7.9 system.
- During explicit Bluetooth recovery, wait for the device to disconnect before reopening its Bluetooth link and discovering the control service again. The ES100 can change its serial channel after reconnecting.
- Recognize an opened control channel when macOS omits the open callback, while preventing duplicate authentication.
- Load paired devices off the main queue so Bluetooth initialization does not freeze the interface.
- Report version **1.0.8 (9)**. Local build output now displays the version and the command for creating a DMG.

### Upgrade and install

Quit any older copy, download **EarStudio-Companion-1.0.8-macOS-universal.dmg**, open it, and drag **EarStudio Companion** into **Applications**. Requires **macOS 14 or newer**, on **Apple Silicon or Intel**.

Allow Bluetooth access if macOS asks again after updating. If the control channel fails to open, use **Reconnect Bluetooth**; this briefly interrupts EarStudio audio. Briefly press the ES100 power button if the app requests device authorization.

This community release is **ad-hoc signed and not notarized by Apple**. If macOS blocks it, attempt to open the app, then use **System Settings → Privacy & Security → Open Anyway** for this intentionally downloaded copy. Keep Gatekeeper enabled.

To verify the download, save the accompanying checksum file beside the DMG and run:

```sh
shasum -a 256 -c EarStudio-Companion-1.0.8-macOS-universal.dmg.sha256
```

### Validation and limitations

- All 80 native Xcode tests passed, including discovery completion, missing callbacks, delayed disconnect state, recovery timeout, and close/reopen errors. The publishing workflow also runs the Swift Package core tests before packaging.
- On macOS 15.7.9, a same-session comparison reproduced the filtered-discovery failure and successful full discovery. Repeated hardware probes opened the serial channel after waiting for disconnection and explicitly reopening the link.
- These probes did not authenticate or change device settings. An earlier diagnostic build reached the ES100's physical authorization prompt after a manual reconnect, but the final 1.0.8 build has not been verified through full settings readback or repeated authenticated reconnects. Broader ES100 MK2 and older-firmware testing remains ongoing.
- The package contains verified Apple Silicon and Intel binaries and a SHA-256 checksum. Firmware flashing and factory reset are not included.

Report problems through [GitHub Issues](https://github.com/igorgarbuz/earstudio-mac/issues), including app/macOS/device firmware versions and sanitized diagnostics.
