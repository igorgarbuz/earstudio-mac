EarStudio Companion 1.0.9 adds 22 Android factory EQ presets, unifies connection and recovery behind one Connect action, clarifies device status, and adds the original product photo to Overview.

### Changes

- Add all 22 recovered Android factory EQ presets under **EQ → Presets → Factory presets**, separate from saved presets. Selecting one applies only preamp and band gains, preserving Q, headroom, analog compensation and EQ enable/bypass. Existing saved presets and XML/JSON import behavior are unchanged.
- Replace the Overview illustration with the same original ES100 product photo used in the README. Bundle the image in the app's asset catalog.
- Replace the custom green bars in the system icon and the sidebar thumbnail with a consistent, static green LED ring inspired by the ES100.
- Label the headphone readout as an output mode. Explain that 2.5 mm balanced can be reported with both sockets empty; this is not proof that headphones are connected.
- Show a bordered **Try demo** button with an **Explore without a device** caption only while disconnected, and **Exit demo** while previewing sample settings. Hide the misleading disabled demo button during a real connection.
- Use a single **Connect** action: try normal opening with a six-second control deadline, retry the control channel once without resetting Bluetooth audio, then use one full Bluetooth reset only if both control attempts fail. Service discovery keeps its separate twenty-second deadline and skips the control retry if it times out. Explain the possible brief audio pause before connecting and show recovery progress. Keep Cancel available, stop after a failed recovery, and ignore late callbacks from replaced attempts. Do not reset for permission/ownership failures or retry authorization/settings writes.
- Report version **1.0.9 (12)**. Build 12 adds the factory presets to the earlier local build 11.

### Connection evidence and limitations

The installed 1.0.8 session on 2026-10-10 recorded two timeouts opening control channel 1 while Bluetooth audio was connected. Explicit Bluetooth recovery then discovered channel 2, authenticated, and read back settings from ES100 firmware 2.0.2. This verifies that the 1.0.8 reset path worked in that session. It does not establish whether the stuck state originated in macOS or the ES100 firmware, or guarantee that every future reconnect succeeds.

The user subsequently confirmed automatic recovery with build 10. Its live diagnostics recorded a stalled control open from 16:42:39 to 16:42:59, pending-channel cleanup until 16:43:00, Bluetooth reset until 16:43:06, and successful authentication/readback by 16:43:07. The roughly 28-second total included a fixed 20-second opening timeout; the full reset interrupted music.

Build 11 reduces each control-opening deadline to six seconds and adds one control-only retry before a full reset. Two stalled control opens therefore spend twelve seconds in opening timeouts rather than twenty; discovery, cleanup and reset time are additional. The control-only retry preserves the baseband link but is not yet verified to repair this physical device’s stuck state. A full reset still interrupts audio and does not automatically resume the music player. No settings writes are replayed. Repeated hardware validation remains necessary.

### Local validation

Before factory-preset integration, all 96 native Xcode tests passed and the universal Release build succeeded. Validation covered control-only retry, opening/discovery deadlines, stopping after one reset, cancellation of subsequent control attempts, retrying the selected device, late callbacks (including a reused channel), permission/authorization boundaries, and the bundled product image. The sidebar was visually checked in an isolated native preview, and the regenerated ring icon was inspected at 16, 32 and 256 pixels. The bundled PNG's SHA-256 matches the README photo.

Four focused native tests passed after factory-preset integration. They check all 220 band values against the extracted Android wire payloads, settings preservation and existing saved-preset behavior. The raw preset tables match across all four Android ABI libraries; native initialization scaling and Java/UI rounding were traced and independently checked. These are static and simulated checks, not a live Android/ES100 audio comparison.

The release publishing script runs both complete test suites, creates a fresh universal archive/DMG, verifies signing and architecture, and checks uploaded asset digests before publication.

### Remaining limitations

The app is ad-hoc signed and not notarized by Apple. Hardware coverage remains limited to the documented ES100 sessions. Cancelling recovery prevents a subsequent control connection, but a Bluetooth reset already executing may finish in the background. The separate authentication-timer and Android saved-preset import improvements discussed during the audit are not included in this release.
